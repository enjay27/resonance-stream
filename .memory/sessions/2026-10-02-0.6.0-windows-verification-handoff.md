2. Run the checks below with Kade. `cargo tauri dev` **as Administrator** (raw socket).
3. **Close a verified item by deleting its bullet** in
   [`active-issues/unverified-on-windows.md`](../active-issues/unverified-on-windows.md)
   (rule in `.memory/README.md`); write what failed, with the evidence, in a new
   `sessions/` note. A failure gets a test first, then a fix, on its own branch.

## C. Known issues and decisions for Kade (not checks)

- **`latest` must always be a signed release.** A manual release without `latest.json`, or a
  non-prerelease candidate, makes updates silently stop (404 = "no update"). A hand-made release
  on a tag also blocks `release.yml` for that tag.
- **Key custody.** Losing both keys strands every 0.6.0 copy (manual reinstall). Keep the key files and
  passwords in two places. A *new* key can only be introduced by a release signed with an old one.
- **Old copies (<= 0.5.x)** still trust the gist (SHA-256 only) until they update; the gist `app`
  entry must stay.
- **Firewall.** A rule cannot be keyed to a signing key (Windows matches program path / service /
  package only), and updates keep the path, so the rule survives them. Option on the table:
  create the rule automatically when missing (the app is already Administrator) -- not built.
- **Waiting on Kade:** A4 (double `<bos>`: re-fine-tune), `class_id` (tag 24, needs a capture),
  cheat-sheet data is not official (`SOURCE_NOTE`), compact-mode hover never looked at.
- **Process:** `rc` was merged into `main` wholesale (#91) although CLAUDE.md says it never is.
  `MEMORY.md` is far over its ~40-line rule; trimming it is its own task.
