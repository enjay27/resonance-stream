**Furigana on'yomi fallback (2026-10-02, `candidate/furigana-kanji-fallback`, off `rc`, PR into `rc`):** a word the analyser has no reading for (`巨塔` -- IPADIC has neither the word nor 巨 alone) is read kanji by kanji in on'yomi (きょ・とう); kana and kanji with no on'yomi (畑, 峠) stay plain; a word with a reading keeps it (山 → やま). **Second rule (same branch):** two or more single-kanji tokens side by side (響奏 = 響 ひびき + 奏 そう -- IPADIC knows each, not the pair) are read in on'yomi too (きょう・そう); a kanji with no on'yomi keeps its own reading; one kanji alone, or next to kana or a longer word (響奏者 = 響 + 奏者), keeps the dictionary's. **Cost:** a real kun'yomi pair the dictionary lacks as one word would flip to on'yomi (山川 is in IPADIC as one word, so it is safe; 泡影 -> ほうえい is right). Pure, in `furigana::spans_from_tokens` + `crates/core/src/kanji_on.rs`; the table (`kanji_on_table.rs`, 2,969 kanji, grade 1-6/8/9/10, first `ja_on`) is **generated by `scripts/gen_kanji_on.py` from KANJIDIC2 (EDRDG, CC BY-SA 4.0 -- credited in the table header and both READMEs)**. IPADIC-per-kanji was rejected: no entry for 巨. Core gate green on a re-encoded 2007 IPADIC (Lindera.dev blocked here); CI uses the official pack. **Open:** in Kade's screenshot lines 1-2 had no ruby on 周 either, and lines with spaces: this lindera build drops spaces (a line that does not read back as itself comes back plain) -- not touched, not reproduced with the 2025 IPADIC.
